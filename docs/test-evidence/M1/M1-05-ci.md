## Outcome and scope

The repository now defines a GitHub Actions workflow for pull requests, pushes to `main`, and manual runs. It separates quality/unit checks, production build verification, live infrastructure integration, and browser smoke tests so failures identify the affected boundary.

Playwright exercises the production Next.js server in desktop Chromium and a Pixel 5 viewport. The smoke test verifies HTTP success, the document title, main heading/landmark, keyboard skip link, and that Phaser/canvas are not eagerly loaded into the invitation shell.

## Acceptance criteria satisfied locally

- CI installs the exact Node and pnpm versions declared by the repository and uses the frozen lockfile.
- Linting, formatting, strict type checking, unit tests, Drizzle metadata, Compose configuration, and runtime audit run in CI.
- The production build and client-bundle secret/infrastructure scan run in CI.
- PostgreSQL, Redis, and BullMQ are exercised against healthy GitHub service containers.
- Browser tests cover desktop and mobile viewports against the production server.
- Failed browser runs upload traces, screenshots, and the HTML report when available.
- Workflow permissions are read-only, actions are pinned to immutable commits, and superseded runs are cancelled.
